# /company/prompts

Versioned prompt templates. Prompts are first-class artefacts:

- Stable name and version
- Declared inputs and expected outputs
- Linked to the agents that consume them

Prompt changes ship through pull requests, not chat windows.

## Frontmatter shape

```yaml
---
name: <kebab-case>
version: 0.1.0
description: <one-line summary>
consumer: <agent path>
audience: <comma-separated roles or canonical IDs>
inputs:
  - <named input>
outputs:
  - <output format>
---
```

## Authoring rules

- One prompt per file. No multi-prompt files.
- Bump `version:` when the prompt's contract changes. Renaming a phrase does not bump.
- Cite the memories the prompt depends on (see [`/company/memory/`](../memory)). Memories are claims; prompts that depend on them carry the link so a future reviewer can verify.
- Never embed secrets, canonical IDs of specific entities, or vendor names. The prompt describes shape, not instance.

## Worked example

[`cash-forecast-summary.md`](./cash-forecast-summary.md) — the weekly brief generated by the `cash-forecaster` agent. Shows: inputs, output template, hard constraints, failure handling, and references to the two memory entries that justify the constraints.
