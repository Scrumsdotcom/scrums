# Maintainers

This file lists the current maintainers of Company-as-Code. Security reports should go through the channels listed in [`SECURITY.md`](./SECURITY.md), not by reaching maintainers directly on public channels.

## Lead maintainer

- **Gerald Neves**: Founder & CEO, [Scrums.com](https://scrums.com)
  - GitHub: [@gez-scrumsdotcom](https://github.com/gez-scrumsdotcom)
  - Security contact: see [`SECURITY.md`](./SECURITY.md)

## Project roles

The project is currently maintained by Scrums.com as a reference implementation for the operating-system pattern behind Scrums.com's **Software Engineering Orchestration Platform (SEOP)**.

External maintainers are added through demonstrated contribution + an ADR proposing the addition. See [`/docs/adr/`](./docs/adr) for the precedent.

## How to reach a maintainer

- **Security vulnerabilities**: private security advisory via GitHub: *Security tab → Report a vulnerability*. See [`SECURITY.md`](./SECURITY.md).
- **Bugs / feature requests**: open an issue using one of the templates under [`.github/ISSUE_TEMPLATE/`](./.github/ISSUE_TEMPLATE).
- **General discussion**: GitHub Discussions when enabled, or open a draft PR with a proposal.
- **Commercial / partnership inquiries**: Scrums.com via [scrums.com](https://scrums.com).

## Decision-making

- Architectural changes go through an [ADR](./docs/adr) that the lead maintainer must accept.
- Non-trivial code changes follow the [plan-first workflow](./CONTRIBUTING.md#1-plan-first-for-non-trivial-work).
- Schema changes follow [`/docs/standards/schema-migrations.md`](./docs/standards/schema-migrations.md).
